"What does amending a commit do in GitHub Desktop, and why should you avoid amending a commit that has already been pushed?", "Amending a commit modifies the most recent commit on your current branch by replacing it with a new commit. It is useful when you need to edit the commit message or forgot to include changes. If the commit has already been pushed, you must force push to overwrite the commit history in the remote repository, which may confuse collaborators who have already based work on the commit."
"What happens when you check out a previous commit in GitHub Desktop, and how can you recover commits made in that state?", "Checking out a commit puts the repository in a 'detached HEAD' state, where HEAD refers to a specific commit that is not on a named branch. The Current Branch item shows 'Detached HEAD' with the commit's SHA. Commits made in this state are lost when you switch branches. To recover them, open the repository in the command line (Repository > Open in command line), run git reflog to find the commit, and then run git cherry-pick with that commit's SHA to apply it to the current branch."
"What is the difference between undoing a commit, resetting to a commit, and reverting a commit in GitHub Desktop?", "Undoing a commit restores that commit's changes to your working directory and resets the branch to the previous commit. You cannot undo a commit that has already been pushed. Resetting to a commit restores the changes from all commits after the selected commit to your working directory and resets the branch to it. You can only reset as far back as the most recent pushed commit. Reverting a commit creates a new commit that reverses the changes of another commit, and the original commit stays in the history, so it is the safe option for commits that have already been pushed."
"In what order should you revert multiple commits in GitHub Desktop, and why?", "You should revert multiple commits in order from newest to oldest. If you revert them in a different order, you may see merge conflicts."
"How do you cherry-pick a commit to another branch in GitHub Desktop?", "In the list of branches, click the branch that has the commit. Select the commit, or select multiple commits using Command (Mac) or Ctrl (Windows) or Shift. Right-click the selection, click Cherry pick commit, and choose the target branch. You can also drag the commit from the History tab onto a branch in the Current Branch dropdown. The current branch then changes to the target branch, and you can push the cherry-picked commit to the remote repository."
"How do you squash commits in GitHub Desktop, and what errors or notifications might you see?", "Select the branch, select the commits to squash, and drop them on the commit you want to combine them with. The commit messages of the selected commits are pre-filled into the Summary and Description fields, so you can edit them before clicking Squash Commits. You may see a notification that a force push is required (click Begin Squash, then Force push origin). You may see an error that the squash failed because there is a merge commit among the squashed commits. You may also see a notification about uncommitted changes, where you can choose Stash Changes and Continue or Close."
"What notifications or errors can occur when reordering commits in GitHub Desktop?", "A force push is required if the reordered commits were previously pushed to the remote branch. The reorder fails if there is a merge commit among the reordered commits. If there are uncommitted changes on the current branch, you can select Stash Changes and Continue, or select Close and commit the changes. If there are merge conflicts, you must resolve them (via View conflicts) before the reorder can continue."
"How can you tell whether a tag has been pushed in GitHub Desktop, and which tags can you delete?", "GitHub Desktop displays an up arrow icon next to a tag that has not been pushed to the remote repository. All tags associated with a commit are visible in that commit's metadata. You can only delete tags associated with commits that have not yet been pushed."
"How does GitHub Desktop run Git hooks, and how is hook output displayed?", "GitHub Desktop runs Git hooks in your configured shell environment, so hooks have access to the same environment variables and tools as when you run Git from the command line. Hooks that rely on version managers such as nvm or rbenv, or on shell configuration files such as .bash_profile or .zshrc, work correctly. Hook output is displayed in real time in the UI, with terminal colors and formatting preserved."
"How can you bypass pre-commit or commit-msg hooks in GitHub Desktop?", "Bypassing hooks is equivalent to git commit --no-verify. Before committing, write your commit message in the Changes tab, click the gear (Commit options) icon next to the message field, select Bypass Commit Hooks, and click Commit to BRANCH. If a hook fails, GitHub Desktop displays the hook's output, and you can click Commit anyway to proceed. Bypassing overrides quality and safety checks that your team may rely on."
"What are Git worktrees, when does the Worktree dropdown appear in GitHub Desktop, and how do you create your first worktree?", "Worktrees let you check out multiple branches of the same repository at the same time, each in its own directory, so you can review a pull request or make a hotfix without stashing or committing incomplete work. The Worktree dropdown appears in the toolbar between the Repository and Branch dropdowns, but only when there is at least one linked worktree. To create your first worktree, click Repository > New Worktree… in the menu bar, or right-click the Repository dropdown in the toolbar."
"When creating a worktree in GitHub Desktop, what happens depending on what you enter in the Branch name field?", "If you leave the field empty, a new branch with the same name as the worktree is created. If you type the name of an existing local branch, that branch is checked out in the new worktree. If you type the name of a remote branch, a new local branch is created from the remote reference."
"What restrictions apply to renaming and deleting worktrees in GitHub Desktop, and what happens if a deletion fails?", "You can rename linked worktrees but not the main worktree. You cannot delete the main worktree or worktrees that Git has locked to prevent deletion. If a deletion fails, for example because the worktree contains uncommitted changes, GitHub Desktop shows an error dialog offering to forcefully delete it. If you cancel, it switches you back to the worktree you were originally working in."
"What happens when you stash changes in GitHub Desktop, and how many stashes can you keep?", "When you stash changes, they are temporarily removed from the files, and you can choose to restore or discard them later. GitHub Desktop only lets you stash one set of changes at a time."
"When does GitHub Desktop show system notifications?", "GitHub Desktop shows system notifications for events in the currently selected repository: when pull request checks have failed, and when a pull request review is left with a comment, an approval, or requested changes. Clicking a notification switches focus to GitHub Desktop and shows more details."
"How does GitHub Desktop display pull request check status, and what re-run options are available?", "A checks badge next to the branch name shows whether checks are pending, passing, or failing. You can re-run all checks, only failed checks (Re-run > Re-run Failed Checks), or individual checks (hover over a check and click the sync icon). A confirmation dialog summarizes the checks to be re-run, and you click Re-run Checks to confirm."
"Can you comment on or merge a pull request from GitHub Desktop?", "No. You cannot comment on a pull request from GitHub Desktop. To add comments, leave a review, or merge the pull request, you must go to the pull request on GitHub. With the pull request branch checked out, click Branch > View Pull Request on GitHub in the menu bar to open it quickly."
"Which custom LLM provider types does Copilot in GitHub Desktop support, and what should you consider before using one?", "GitHub Desktop supports three custom provider types: OpenAI / OpenAI-compatible (OpenAI, Ollama, vLLM, Foundry Local, and other compatible endpoints), Azure (Azure OpenAI Service), and Anthropic (Claude models). Using one requires access to Copilot in GitHub Desktop. Prompts and repository context are sent to your provider instead of GitHub, so check its data handling and retention policies. Always review generated commit messages and conflict-resolution suggestions before committing."
"How does GitHub Desktop determine the author name and email for commits, and what is the default branch name for new repositories?", "GitHub Desktop detects and uses the name and email already set in your global Git configuration, or you can set them in the Git settings. You can also set a different name and email for an individual repository, which overrides the global configuration, for example to use a work email. If the configured email doesn't match an email on the GitHub account you're signed in to, GitHub Desktop shows a warning before committing. By default, new repositories use main as the default branch, which you can change on the Default branch tab of the Git settings."
"What protocol does GitHub Desktop use to connect to GitHub, and what should you do if a repository was cloned using SSH?", "GitHub Desktop connects to GitHub using HTTPS and caches your credentials (username and password or personal access token) to authenticate each connection. Repositories cloned using SSH may cause errors, so you should change the remote's URLs."
